# D3 验证记录

日期：2026-11-16（Asia/Shanghai）。范围仅为证据需求审计、一次补检、图数据和实际轨迹；不开发 3D 展示。

## 实现

- 复用 D2 依赖，未安装新框架或下载向量模型。D2 两项关键基线复核通过，基础模式保持兼容。
- 规划 1–4 个需求，初次 BM25 检索，有限术语共现扩展，按需求验证，至多一轮针对缺口的补检，随后停止。对未询问的方法全称/缩写释义等任务进行保守裁剪，避免额外任务抬高覆盖分母。
- 需求仅在模型提出直接支持、原文引句匹配、回答有效时计为 supported；回答与解释里的拉丁术语、数字还需在该需求所引用片段中出现。失败候选保留审计原因，仍不构成语义证明。新增记录含 audit_version；旧版审计记录提示重新执行，不伪装已应用新保护。
- 每步骤最多一次格式重试，计入全局最多 6 次模型请求；模型调用共享默认 100 秒截止预算，单次仍受 LLM_TIMEOUT_SECONDS 限制。网络或服务错误停止，不无限循环。已支持的需求在后续失败时保留。
- 原文规则提取每个片段至多 3 个术语，并保存 term / chunk / 字符位置 / 规则版本到 SQLite。每次检索最多扩展 2 个共享术语片段。无术语、索引失败或显式关闭时退化为 Paper–Chunk–Requirement 来源图并明示。
- 图仅包含本轮实际访问的论文、片段、术语与需求。contains、mentions、supports 逐条携带出处；支持边指向经过原文匹配的审计记录，不随机生成节点或实体关系。
- 需求、证据、graph、trace、停止原因与统计一起保存在原 query_runs JSON 中；旧 D2 记录兼容读取，不虚构历史审计。当前网页默认审计模式，API 默认基础模式兼容 D2。
- 前端只增加需求状态、支持来源入口与完成后的真实轨迹文本；不实现 D4 的 3D、来源链高亮或动画回放。

## 重要限制

- supported 是“模型提出直接支持 + 可定位引文 + 有效回答”的原型审计状态，不是科学事实认证，也不是独立的蕴含证明。
- 拉丁术语/数字检查可能保守拒绝等价改写、不同数字表达或跨语言表述；仍不能识别所有中文语义错误。未要求释义任务的裁剪也不等于完整的需求相关性验证。
- 术语共现可能仅是文字相关，不是语义知识图谱；不是完整 KG2RAG 或 LightRAG 的复现。
- 真正模拟的预算、超时、坏输出和上游失败由隔离测试验证，未为测试耗尽用户额度或修改密钥。
- 原生 PDF 阅读器跳页沿用 D1 未复核项；应用内片段与页码可查询，不将系统 Edge 的检查写成已通过。
- 只有一条真实含缺口的问题；完整五题和补检开关对比留到 D5，不杜撰研究指标。
