# 《同节异俗》｜设计阶段审查与下一轮决策

日期：2026-11-16。基线：VerifiAtlas D6 `bf953027528630796ef37b78baaeab2cbf8d803c`。工作分支：`design/cultural-exploration`。新远程：`https://github.com/iuqllTo2048/Festive-Mosaic`。这是独立设计阶段，不是原 D7；完成后等待设计审核，不自动进入正式文化迁移。

## 1. 最终定位

**《同节异俗——基于多源文化证据的传统节俗交互探索系统》**，首期端午，采用苏州、汨罗江畔、西塞三个地方资料对象。通过“选择问题 → 观察实践 → 双主题对照 → 回读依据 → 保存发现和问题”理解地方文化的联系与差异。

设计语言为现代文化档案与编辑式阅读：纸本、炭墨、赭红、青灰绿；原创舟形剖面介绍“实践—解释—依据”。无地图、聊天入口或装饰性粒子。收藏和资料抽屉是通用模式，本项目的设计重点在于它们组成文化并读的方法，不宣称发明这些基础功能，也不保证竞赛结果。

## 2. 已完成页面与真实交互

- 首页：三道完整文化问题、原创SVG图版、资料与DEMO说明。
- 文化层理工作台：地方筛选、纪念/实践/节期维度、Three.js三层关系、节点/关系点击、层次聚焦、旋转、平面读图、复位和同源列表。
- 异俗对照：两个主题与比较维度选择；由feature交集生成中央共享元素；保留地方解释与独立资料列；共同元素可切换双方出处。
- 说法剖面：实践、解释、短定位摘录、资料主体/段落/链接/日期、来源状态；候选关系显示不足，不伪造支持来源。
- 个人观察档案：收藏/移出关系、本地保存问题及文化对象、共同元素提示、用户手写待查问题；刷新恢复。没有账号、云同步或真实导出服务。

原型共3个文化对象、9条来源可定位的编辑摘编、1个无支持的候选问题。4条来源目录中S04只作背景。没有调用DeepSeek，没有真实检索/补检运行。独立人工语义核验为0；所有文化关系及feature归类均为 **provisional / 待独立人工审读**。

## 3. 三个辨识度最高的设计点

1. **三层阅读而非装饰网络**：地方实践在上、解释在中、资料在下。一个点击展开完整说法和依据；二维列表保留同一组信息入口。
2. **共同元素显现，地方解释保留**：苏州/汨罗实践维度在中央出现竞渡；切换西塞后保留独立记录，不用“无交集”暗示当地不存在该习俗。
3. **档案同时保存发现与空白**：不生成权威报告。用户从实际浏览中收藏关系并写问题，证据不足仍可作为待查问题，而不是被系统填造结论。

这些是可操作的设计取向，尚未经过真实学生可用性测试。

## 6. 文化内容与版权风险

已直接读取苏州地方官方、中国非遗网汨罗/西塞项目及端午专题；短定位摘录分别展示，不拼成连续引文。UNESCO直接访问遇到验证，未绕过，不作为地方细节出处。详细链接、类别与限制在 [研究札记](00_RESEARCH.md)。

来源已定位不能变成语义认证。西塞保留祈愿与屈原纪念关联的多重叙述；不同地方解释可以并存。节期是条目的一般农历记录，不是2026年度日程。

没有下载第三方照片、视频、音频或字体。SVG与几何示意为原创，非具体文物复原。正式参赛仍需核对短摘编使用方式、全部新增素材授权、地方文化表达适宜性和赛事AI披露要求。
